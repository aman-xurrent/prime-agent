## Phase 3 workflow

This changeset is all about contracts. We need to develop the exact interface changes to make this
changeset happen.

* identify the methods/functions that need to be created to implement this feature
* identify the methods/functions that need to change.
  ** change the method/function signature, but do not change the body
* if there is class/module-level data, create it now.
* if you change a signature of an existing method/function DO NOT DELETE THE BODY
* if you change a signature of an existing method/function DO NOT EDIT THE BODY

## Phase 3 done criteria

- [ ] update to latest main before proceeding
- [ ] IT IS OK TO CHANGE THE SIGNATURE OF A METHOD/FUNCTION
- [ ] Every new/changed method/function has a stub body only (`raise NotImplementedError` for Ruby, or an equivalent behavior-free stub for TypeScript).
- [ ] New constants and class/module-level data are private where applicable, zero/default-value, and behavior-free.
- [ ] No structure/model/interface/type edits (unless user escalated to Phase 2).
- [ ] No wiring, call sites, or behavioral logic added.
- [ ] DO NOT VERIFY BUILD
- [ ] DO NOT RUN TESTS
- [ ] request/ticket is moved to review column and assigned to me.
- [ ] Phase 3 commit pushed and **PR created or updated immediately**.
- [ ] internal note is published saying **Phase 3: {pr link} {Created/Updated}**
